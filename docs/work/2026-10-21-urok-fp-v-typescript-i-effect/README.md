## Задача

Урок «ФП в TypeScript и Effect» сам выбери лучшие практики

## Бриф

### Коротко

Это урок 25 «ФП в TypeScript и Effect» (`fp-in-typescript-and-effect`), поток W4 из плана задачи 7. Мост от JS-курса к продакшену: сквозной пример «онлайн-пользователь старше 20» из урока «Функциональное программирование» переписан на Effect 4. TS-код только для чтения, с подсветкой. Упражнения на JS, их исполняет тест. Владелец передал решения нам, все 12 приняты ниже. Главный риск — фактическая точность про Effect под именем автора-специалиста: почти все материалы в сети написаны под v3, а API v4 местами другое (сверено по типам пакета, таблица ниже).

### Что просят

Написать на RU и EN урок, который в плане задачи 7 отложили до тезисов владельца. Владелец ответил: «сам выбери лучшие практики». Значит, 12 вопросов из «Что нужно от владельца» задачи 7 закрываем сами и обосновываем. Урок встаёт под номер 25 между `neural-networks` и `selecting-library`, «Что выбрать» сдвигается на 26. Вместе с уроком приходят TS-блоки кода по решению плана 9 задачи 7 (с поправкой, см. «Известно точно»), а урок возвращается в порядок курса и в приёмку C.

### Решения, принятые за владельца

1. **Цель урока.** «Увидеть, как идеи курса — композиция через pipe, Maybe и Either, эффекты как значения — выглядят в TypeScript на Effect 4, научиться читать тип Effect<A, E, R> и решать, когда переход на Effect окупается» (204 знака; EN 208, лимит теста — 300). *Почему:* урок-мост. Он показывает не новый материал, а знакомые идеи в продакшен-инструменте и заканчивается решением «брать или нет», которое подводит к «Что выбрать».
2. **Читатель.** JS-разработчик, прошедший курс. TS умеет читать, но не обязательно писать. Аннотации, union-типы и дженерики объясняются при первом появлении, через уже знакомую нотацию Хиндли–Милнера: `head :: [a] -> Maybe a` рядом с `head: <A>(self: ReadonlyArray<A>) => Option<A>`. *Почему:* курс на JS, и «Для кого» требует только опыта в JS. Мост через урок «Нотация типов Хиндли–Милнера» не требует отдельного введения в TS.
3. **Версия — Effect 4.** В тексте: «Effect 4: версия 4.0.0 вышла 1 октября 2026 года, ветка 3.x ещё получает исправления (по данным реестра npm на октябрь 2026 года)». Номера патча нет (F10 задачи 7), формулировка дословно совпадает с `selecting-library`. Одна фраза о том, что в v3 модуль Result назывался Either. *Почему:* `latest` = 4.0.5; README пакета называет 4.x LTS-релизом с исправлениями не меньше трёх лет; все модули урока помечены `@stability stable`. Через год v3-примеры устарели бы, а урок под именем специалиста должен показывать текущий API.
4. **Темы.**
   - **Обязательные:** типизированный `pipe`, а `flow` одной фразой; `Option` и `Result` в сравнении с Maybe и Either из урока «Maybe и Either» (таблица соответствий); `Effect<A, E, R>`: эффект как ленивое значение и канал ошибок с тегами (`Data.TaggedError`, `Effect.catchTag`); `Effect.gen`, читается «как async/await»; `Schema` для проверки данных на границе.
   - **Только упомянуть, без кода:** R, `Context` и `Layer` (зависимость видна в типе, а `Effect.runPromise` принимает только эффект с R = never); конкурентность, повторы и тайм-ауты (`Effect.all` с `concurrency`, `Effect.retry`, `Effect.timeout`).
   - **Опустить:** Fiber API, Stream, Scope, STM, классы типов и HKT, платформенные модули `effect/*`.

   *Почему:* объём урока по правилам курса — 6–12 текстовых блоков и 2–5 блоков кода. Темы из списка «обязательные» прямо продолжают уроки курса. Context/Layer без кода абстрактны и требуют второго урока.
5. **Сквозной пример.** «Онлайн-пользователь старше 20» из `functional-programming.ts:25-181` в три шага.
   - Чистая часть: `pipe` + `Array.filter`/`Array.head`/`Option.map`/`Option.getOrElse`, один к одному с `S.pipe`/`S.head`/`S.fromMaybe`, результат тот же — `'John'`.
   - Данные «с сервера» проверяет `Schema`. Это та защита во время выполнения, о которой говорит комментарий урока 02 (`functional-programming.ts:85-89`).
   - Вся программа — `Effect.gen` с ошибками в типе, например `Effect<string, FetchError | UserNotFound>`, и обработкой через `catchTag`.

   «Сервер» имитируется фиксированными данными, сети нет. *Почему:* так мост виден буквально: та же задача, тот же ответ, и видно, что дал каждый слой.
6. **Где окупается.** Окупается, где у ошибки высокая цена:
   - бэкенд и интеграции с несколькими точками отказа (сеть, БД, очереди): ошибки в типе, повторы, тайм-ауты и отмена встроены;
   - долгоживущий код, который правят многие: компилятор показывает необработанные ошибки и незакрытые зависимости;
   - внешние данные: Schema даёт тип и проверку из одного описания;
   - конкурентность с ограничением параллелизма и отменой;
   - тесты с подменой сервисов через Layer.

   **Где не окупается:**
   - скрипты, прототипы, простой CRUD-фронт;
   - команда без TS или без времени на обучение, частая смена людей;
   - клиентская страница, где важен каждый килобайт: размер бандла измеряют на своём проекте, цифр в уроке нет.

   *Почему:* это совпадает с критериями «Что выбрать» (бюджет, этап, команда), и обе стороны там уже описаны.
7. **Почему курс на JS.** Нейтрально, без первого лица: идеи ФП не зависят от системы типов, на JS они видны без лишнего синтаксиса; в продакшене их часто пишут на TypeScript, где отсутствие значения и ошибки становятся частью сигнатуры и их проверяет компилятор. *Почему:* так решено в задаче 7 (вопрос 3а). Голос автора в остальном курсе неровный, нейтральный тон безопаснее под именем специалиста.
8. **fp-ts.** Один абзац без кода: предшественник; по README fp-ts проект объединился с экосистемой Effect, а Effect «можно считать преемником fp-ts v2»; последний релиз — 2.16.11 от 18 августа 2025 года. Для нового кода — Effect, fp-ts — там, где он уже есть. *Почему:* это проверено по README и реестру, совпадает с `selecting-library.ts:240-257`, и равноправным вариантом fp-ts подавать было бы фактически неверно.
9. **Оценки в таблице «Что выбрать».** Подтверждаем черновик без изменений (`selecting-library.ts:311-397`). Они согласованы с текстом после F3 и F4 задачи 7: строгость 4 из 5 и производительность 2 из 5 у обоих, порог входа высокий, этап у fp-ts — «если уже в проекте». **Одна правка-условие:** фразу «в версии 4 рантайм переписан и бандл заметно уменьшен» (`:287-288`) в README и типах пакета подтвердить не удалось. W4 сверяет её через context7 (руководство по миграции и анонс v4) и записывает источник в карточку. Если источника нет, остаток фразы после «(tree shaking)» убирается в ru и en. *Почему:* урок 25 не должен ни противоречить «Что выбрать», ни повторять непроверенное.
10. **Запуск кода — вариант (а).** TS-блоки только для чтения, с подсветкой и пометкой «TypeScript», без кнопки «Открыть в песочнице». 1–2 упражнения на чистом JS без Effect, песочница и тест их исполняют. Варианты: «эффект — описание, а не действие» (ленивое описание, счётчик вызовов показывает, что при сборке ничего не запускается) и «ошибки с тегом» (результат `{ _tag: 'Success' | 'Failure' }`, разбор по `_tag`). *Почему:* без сети и esm.sh, без новых зависимостей, упражнения покрыты тестом. Тип TS-кода проверяет `tsc --strict` в scratchpad.
11. **Внешние ссылки.** Ссылок нет. Один раз адрес текстом — «документация Effect: effect.website» в последнем абзаце. GitHub автора не упоминаем. *Почему:* в модели текста ссылок нет. Официальный домен стабилен и даёт читателю следующий шаг. Ссылка на себя в уроке выглядела бы рекламой.
12. **Названия.** Урок 25: «ФП в TypeScript и Effect» / «FP in TypeScript and Effect», slug из плана. Урок 26 переименовать в «Как выбрать библиотеку для ФП» / «How to choose an FP library», slug не меняется. *Почему:* нынешнее «Vanilla JS, Lodash, Ramda, Sanctuary -> что выбрать» не называет fp-ts и Effect. QA задачи 7 нашёл две стрелки подряд в «Продолжить: … -> что выбрать →» (оговорка 7), а самое длинное название даёт сдвиг сводки на 375 px до 99 px (повторный прогон, оговорка 1). Описание урока 26 уже перечисляет все шесть вариантов.

Плюс вопрос 14 задачи 7: `functional-programming.ts` не трогаем, текст там уже нейтральный, а ссылки вперёд по правилам курса — редкость.

### Известно точно

- **База.** HEAD `nuxt4` = 7f8bf96, задача 7 влита. Уроков 25, порядок в `app/data/course.ts:32-58`. В приёмке C `LESSON_ORDER` на 25 slug, комментарий `:32-35` ждёт этот урок.
- **Реестр npm (21.10.2026).**
  - effect: `latest` 4.0.5 (15.10.2026), `prev` 3.22.3 (16.10.2026). 4.0.0 вышел 01.10.2026 после 107 beta и 11 rc.
  - README effect 4.0.5: «Effect 4.x is a long-term support (LTS) release, with at least three years of bug and security fixes». Требования: TypeScript 5.9+, `strict: true`, Node 18+.
  - fp-ts: 2.16.11 (18.08.2025). README: «Effect-TS can be regarded as the successor to fp-ts v2», «fp-ts project is officially merging with the Effect-TS ecosystem».
- **Различия v3 и v4, которые затронут примеры.** Сверено по `.d.ts` пакетов effect 3.22.3 и 4.0.5 из реестра:

  | v3 | v4 |
  |---|---|
  | модуль `Either` (Right/Left), `Effect.either` | модуль `Result` (Success/Failure), `Effect.result`; `Either` в v4 нет |
  | `Option.fromNullable` | `Option.fromNullishOr` |
  | `Effect.catchAll` | `Effect.catch` |
  | `Context.Tag`, `Context.GenericTag` | `Context.Service<Self, Shape>()("Key")` |
  | `Schema.decodeUnknown` → `ParseError` | `Schema.decodeUnknownEffect` → `SchemaError` (есть `decodeUnknownSync`) |
  | `Schema.Literal("a", "b")` | `Schema.Literals(["a", "b"])`, а `Literal` принимает один литерал |
  | Option и Either — подтипы Effect, `yield*` прямо в `Effect.gen` | Option и Result не Effect; `Effect.gen` принимает `Generator<Eff extends Effect>`, переход через `Effect.fromOption` / `Effect.fromResult` |
  | `Effect.tryPromise(fn)` → `Cause.UnknownException` | → `Cause.UnknownError` |

  Не изменились: `Effect.gen`, `Effect.fail/succeed`, `Effect.runPromise` (в v4 — `Effect<A, E>`, то есть R = never), `Effect.catchTag`, `Data.TaggedError`, `Schema.Struct/String/Number`, `Option.map/getOrElse`, `Array.head`, `pipe` и `flow` из корня `effect`, `Layer.succeed`.
