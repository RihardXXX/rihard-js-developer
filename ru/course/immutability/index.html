06 Иммутабельность

Цель урока Научиться обновлять объекты и массивы без мутаций — копированием через spread и structuredClone, немутирующими методами массивов и функциями Ramda — и понимать, где копия поверхностная и чего она стоит.

Иммутабельные данные не меняются после создания: чтобы «изменить» объект, создают новый, а прежний остаётся как был. В уроке «Чистые функции» так уже делали: changeAge возвращала нового пользователя через spread. Здесь разберём, зачем это нужно, где копия получается поверхностной, как защититься от случайной мутации и во что обходятся копии.

Почему мутации ломают предсказуемость

Переменная с объектом или массивом хранит ссылку на него, и при присваивании или передаче в функцию копируется ссылка, а не сам объект. Поэтому переменная, аргумент функции и поле другого объекта могут указывать на один и тот же объект. Если одна часть программы его меняет, изменение видят все остальные, и ошибка проявляется далеко от места мутации: чтобы её найти, нужно выяснить, у кого ещё есть ссылка на этот объект.

// Мутация аргумента
// ===============================
// bestScoreImpure :: [Number] -> Number
// НЕчистая: sort сортирует сам переданный массив
const bestScoreImpure = (scores) => scores.sort((a, b) => b - a)[0]

const scores = [40, 95, 70]
console.log(bestScoreImpure(scores)) // 95
console.log(scores) // [95, 70, 40]: исходный порядок потерян

// Общий объект
// ===============================
const defaults = { theme: 'light', fontSize: 14 }

const userSettings = defaults // копируется ссылка, а не объект
userSettings.theme = 'dark'

console.log(defaults.theme) // dark: значения по умолчанию тоже изменились

// Без мутаций
// ===============================
const baseSettings = { theme: 'light', fontSize: 14 }
const darkSettings = { ...baseSettings, theme: 'dark' } // новый объект

console.log(`${baseSettings.theme} -> ${darkSettings.theme}`) // light -> dark

const здесь не помогает: он запрещает присвоить переменной другое значение, но не мешает менять объект, на который она ссылается. Объявление const defaults не делает объект неизменяемым — для этого нужна копия или Object.freeze.

Поверхностная и глубокая копия

Spread создаёт новый объект ({ ...obj }) или массив ([...arr]), но копирует только верхний уровень: вложенные объекты и массивы остаются общими с оригиналом. То же верно для Object.assign({}, obj), arr.slice() и Array.from(arr). Чтобы безопасно изменить вложенное поле, копируют каждый уровень на пути к нему, а остальные ветки берут как есть. Это называют структурным разделением: новый объект делит с прежним всё, что не менялось.

// Поверхностная копия
// ===============================
const user = { name: 'Anna', address: { city: 'Moscow' }, tags: ['js'] }

const shallow = { ...user }
shallow.name = 'Olga' // верхний уровень скопирован: у user имя прежнее
shallow.address.city = 'Kazan' // address общий: город меняется и у user

console.log(user.name) // Anna
console.log(user.address.city) // Kazan

// Копия каждого уровня на пути к изменению
// ===============================
const original = { name: 'Anna', address: { city: 'Moscow' }, tags: ['js'] }

const moved = {
  ...original,
  address: { ...original.address, city: 'Kazan' },
}

console.log(original.address.city) // Moscow
console.log(moved.address.city) // Kazan
console.log(moved.tags === original.tags) // true: неизменная ветка общая

// Глубокая копия
// ===============================
const deep = structuredClone(original)
deep.tags.push('fp')

console.log(original.tags) // ["js"]
console.log(deep.tags) // ["js", "fp"]

structuredClone копирует структуру целиком, на любую глубину: вложенные объекты и массивы, Date, Map, Set и даже циклические ссылки. Функции он копировать не умеет и бросает DataCloneError, а экземпляр класса превращается в обычный объект: прототип и методы класса теряются. JSON.parse(JSON.stringify(obj)) теряет больше: Date становится строкой, Map и Set — пустыми объектами, поля со значением undefined и функциями пропадают, NaN превращается в null. structuredClone есть во всех основных браузерах с 2022 года и в Node.js с версии 17.

Object.freeze

Object.freeze запрещает добавлять, удалять и менять свойства объекта и возвращает тот же объект. Заморозка поверхностная: вложенные объекты остаются изменяемыми, их замораживают отдельно. Что произойдёт при попытке записи, зависит от режима: в нестрогом режиме присваивание молча игнорируется, в строгом бросается TypeError. Код в песочнице курса исполняется в нестрогом режиме, а код ES-модулей (файлов с import и export) и тел классов всегда строгий: там та же запись бросит TypeError.

// Object.freeze
// ===============================
const config = Object.freeze({ mode: 'prod', limits: { requests: 100 } })

// нестрогий режим: присваивание молча игнорируется
config.mode = 'dev'
console.log(config.mode) // prod

// строгий режим: та же запись бросает TypeError
const setModeStrict = () => {
  'use strict'
  config.mode = 'dev'
}

try {
  setModeStrict()
} catch (error) {
  console.log(`строгий режим: ${error.name}`) // строгий режим: TypeError
}

// методы массива бросают TypeError в любом режиме
const frozenList = Object.freeze([1, 2])

try {
  frozenList.push(3)
} catch (error) {
  console.log(`push: ${error.name}`) // push: TypeError
}

// заморозка поверхностная: вложенный объект можно менять
config.limits.requests = 1
console.log(config.limits.requests) // 1
console.log(`config: ${Object.isFrozen(config)}, limits: ${Object.isFrozen(config.limits)}`) // config: true, limits: false

Исключение из правила нестрогого режима — встроенные методы: push, sort и другие мутирующие методы на замороженном массиве бросают TypeError всегда, потому что спецификация требует от них ошибки, если запись не удалась. Object.freeze помогает поймать случайную мутацию, но копий не делает: новое значение по-прежнему создаётся через spread или structuredClone.

Немутирующие методы массивов

Часть методов массива меняет сам массив: push, pop, shift, unshift, splice, sort, reverse, fill и copyWithin. Другие возвращают новый массив и исходный не трогают: map, filter, concat, slice. В ES2023 появились немутирующие версии сортировки, разворота, splice и замены элемента.

Мутирующие методы массива и их замены без мутации
ЗадачаМеняет массивВозвращает новый массив
Добавить в конецpush(x)concat(x) или [...arr, x]
Отсортироватьsort(fn)toSorted(fn) или [...arr].sort(fn)
Развернутьreverse()toReversed() или [...arr].reverse()
Удалить или вставить элементыsplice(start, count, ...items)toSpliced(start, count, ...items) или slice и spread
Заменить элементarr[i] = xwith(i, x) или map

toSorted, toReversed, toSpliced и with вошли в стандарт ES2023. Их поддерживают Chrome и Edge с версии 110, Firefox со 115, Safari с 16 и Node.js с 20. Если проект должен работать в браузерах старше, копируйте массив и вызывайте мутирующий метод на копии ([...arr].sort(fn)) или подключите полифил.

// Немутирующие методы массивов
// ===============================
const scores = [40, 95, 70]

// bestScore :: [Number] -> Number
// toSorted из ES2023 сортирует копию; без ES2023 то же: [...list].sort((a, b) => b - a)[0]
const bestScore = (list) => list.toSorted((a, b) => b - a)[0]

console.log(bestScore(scores)) // 95

const added = scores.concat(60) // вместо push
const replaced = scores.with(1, 90) // вместо scores[1] = 90
const withoutFirst = scores.toSpliced(0, 1) // вместо splice(0, 1)
const reversed = scores.toReversed() // вместо reverse()

console.log(added) // [40, 95, 70, 60]
console.log(replaced) // [40, 90, 70]
console.log(withoutFirst) // [95, 70]
console.log(reversed) // [70, 95, 40]
console.log(scores) // [40, 95, 70]: исходный массив не изменился

Ramda: assoc, assocPath и evolve

Функции Ramda не меняют свои аргументы. R.assoc(key, value, obj) возвращает копию объекта с новым значением ключа, R.assocPath(path, value, obj) делает то же по вложенному пути, а R.evolve(transformations, obj) применяет функции к перечисленным ключам, в том числе вложенным, и оставляет остальные как есть. Копируются только объекты на пути к изменению, остальные ветки общие с исходным объектом, как при spread вручную. Обобщение этой идеи — линзы, им посвящён урок «Линзы».

// assoc, assocPath и evolve берём из Ramda: в песочнице курса она доступна как R
// ===============================
const post = {
  title: 'Immutability',
  author: { name: 'Anna', city: 'Moscow' },
  stats: { views: 10, likes: 2 },
  tags: ['js'],
}

// R.assoc: копия с новым значением ключа
const renamed = R.assoc('title', 'Immutable data', post)

// R.assocPath: копия с новым значением по вложенному пути
const moved = R.assocPath(['author', 'city'], 'Kazan', post)

// R.evolve: функции для нужных ключей, остальные ключи без изменений
const viewed = R.evolve({ stats: { views: (n) => n + 1 }, tags: (tags) => [...tags, 'fp'] }, post)

console.log(renamed.title) // Immutable data
console.log(moved.author.city) // Kazan
console.log(viewed.stats.views) // 11
console.log(viewed.tags) // ["js", "fp"]

// исходный пост не изменился
console.log(`${post.title}, ${post.author.city}, ${post.stats.views}, ${post.tags.length}`) // Immutability, Moscow, 10, 1

// неизменные ветки общие с исходным постом
console.log(moved.stats === post.stats) // true
console.log(viewed.author === post.author) // true

Цена копирования

Копия не бесплатна: spread проходит по всем ключам или элементам верхнего уровня, structuredClone — по всей структуре. Для одного обновления это незаметно, но в цикле копии складываются. Частая ловушка — reduce с аккумулятором [...acc, x]: на каждом шаге копируется весь накопленный массив, и для n элементов набирается около n²/2 копирований элементов. Для 1000 элементов это 499 500 копирований, для 10 000 — почти 50 миллионов.

Иммутабельность важна на границах — там, где данные видит кто-то ещё. Массив, который функция создала сама и ещё никому не отдала, можно спокойно наполнять через push: снаружи этого не видно, и функция остаётся чистой. Для больших коллекций, которые часто обновляются, есть библиотеки со структурным разделением: Immutable.js с персистентными структурами данных и Immer, в котором пишут обычный «мутирующий» код для черновика, а получают новый объект.

Главное

  • При присваивании и передаче в функцию копируется ссылка на объект, а не сам объект: мутация в одном месте видна везде, где есть ссылка на тот же объект. const запрещает переприсваивание, но не изменение объекта.
  • Spread, Object.assign и slice копируют только верхний уровень. Для вложенного изменения копируют каждый уровень на пути к нему, для полной копии есть structuredClone.
  • Object.freeze поверхностный: в нестрогом режиме запись в замороженное свойство молча игнорируется, в строгом бросается TypeError.
  • Вместо push, sort, reverse и splice берите concat, slice и spread или методы ES2023 toSorted, toReversed, toSpliced и with. R.assoc, R.assocPath и R.evolve обновляют объекты без мутаций.
  • Копии стоят времени и памяти: [...acc, x] в reduce даёт квадратичную сложность. Локальный массив, который ещё никто не видит, можно наполнять через push.

Упражнения

Упражнение 1

Функции addScoreImpure и topThreeImpure меняют массив, который им передали. Напишите чистые addScore и topThree: первая возвращает новый массив с добавленным результатом, вторая — три лучших результата по убыванию. Исходный массив scores должен остаться прежним.

Заготовка

// addScoreImpure :: ([Number], Number) -> [Number]
// НЕчистая: push меняет переданный массив
const addScoreImpure = (scores, score) => {
  scores.push(score)
  return scores
}

// topThreeImpure :: [Number] -> [Number]
// НЕчистая: sort сортирует переданный массив
const topThreeImpure = (scores) => scores.sort((a, b) => b - a).slice(0, 3)

// addScore :: ([Number], Number) -> [Number]
// topThree :: [Number] -> [Number]
// ваш код

const scores = [40, 95, 70, 85]
const updated = addScore(scores, 60)

console.log(`лучшие три: ${topThree(updated).join(', ')}`)
console.log(`исходный массив: ${scores.join(', ')}`)
console.log(`новый массив: ${updated.join(', ')}`)

Ожидаемый вывод

лучшие три: 95, 85, 70
исходный массив: 40, 95, 70, 85
новый массив: 40, 95, 70, 85, 60
Показать решение
// addScoreImpure :: ([Number], Number) -> [Number]
// НЕчистая: push меняет переданный массив
const addScoreImpure = (scores, score) => {
  scores.push(score)
  return scores
}

// topThreeImpure :: [Number] -> [Number]
// НЕчистая: sort сортирует переданный массив
const topThreeImpure = (scores) => scores.sort((a, b) => b - a).slice(0, 3)

// addScore :: ([Number], Number) -> [Number]
// новый массив вместо push
const addScore = (scores, score) => [...scores, score]

// topThree :: [Number] -> [Number]
// сортируем копию; в ES2023 то же самое делает scores.toSorted((a, b) => b - a)
const topThree = (scores) => [...scores].sort((a, b) => b - a).slice(0, 3)

const scores = [40, 95, 70, 85]
const updated = addScore(scores, 60)

console.log(`лучшие три: ${topThree(updated).join(', ')}`)
console.log(`исходный массив: ${scores.join(', ')}`)
console.log(`новый массив: ${updated.join(', ')}`)

Упражнение 2

Функция moveToImpure меняет город прямо в переданном состоянии. Напишите чистую moveTo(city, state): скопируйте через spread каждый уровень на пути state.user.address. Затем напишите moveToRamda с тем же результатом через R.assocPath. Проверьте, что исходное состояние не изменилось, объект user новый, а ветка cart, которую вы не трогали, осталась общей.

Заготовка

const state = {
  user: { name: 'Anna', address: { city: 'Moscow', zip: '101000' } },
  cart: [{ title: 'book', qty: 1 }],
}

// moveToImpure :: (String, Object) -> Object
// НЕчистая: меняет переданное состояние
const moveToImpure = (city, state) => {
  state.user.address.city = city
  return state
}

// moveTo :: (String, Object) -> Object
// moveToRamda :: (String, Object) -> Object
// ваш код: moveTo через spread, moveToRamda через R.assocPath

const next = moveTo('Kazan', state)

console.log(`было: ${state.user.address.city}, стало: ${next.user.address.city}`)
console.log(`user новый: ${next.user !== state.user}`)
console.log(`cart общий: ${next.cart === state.cart}`)
console.log(`R.assocPath даёт то же: ${JSON.stringify(moveToRamda('Kazan', state)) === JSON.stringify(next)}`)

Ожидаемый вывод

было: Moscow, стало: Kazan
user новый: true
cart общий: true
R.assocPath даёт то же: true
Показать решение
const state = {
  user: { name: 'Anna', address: { city: 'Moscow', zip: '101000' } },
  cart: [{ title: 'book', qty: 1 }],
}

// moveToImpure :: (String, Object) -> Object
// НЕчистая: меняет переданное состояние
const moveToImpure = (city, state) => {
  state.user.address.city = city
  return state
}

// moveTo :: (String, Object) -> Object
// новые объекты только на пути state -> user -> address, cart берём как есть
const moveTo = (city, state) => ({
  ...state,
  user: {
    ...state.user,
    address: { ...state.user.address, city },
  },
})

// moveToRamda :: (String, Object) -> Object
const moveToRamda = (city, state) => R.assocPath(['user', 'address', 'city'], city, state)

const next = moveTo('Kazan', state)

console.log(`было: ${state.user.address.city}, стало: ${next.user.address.city}`)
console.log(`user новый: ${next.user !== state.user}`)
console.log(`cart общий: ${next.cart === state.cart}`)
console.log(`R.assocPath даёт то же: ${JSON.stringify(moveToRamda('Kazan', state)) === JSON.stringify(next)}`)
