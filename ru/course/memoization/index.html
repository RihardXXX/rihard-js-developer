16 Мемоизация

Цель урока Понять, как мемоизация кэширует результаты чистой функции, научиться писать свою memoize и пользоваться R.memoizeWith, выбирать ключ кэша, ускорять рекурсию и учитывать цену памяти и инвалидацию.

Мемоизация — это кэширование результатов функции по её аргументам. При первом вызове функция считает результат и запоминает его, а при повторном вызове с теми же аргументами возвращает сохранённое значение и не считает заново. Термин ввёл британский исследователь Дональд Мичи в 1968 году.

Кэш живёт в замыкании: функция memoize возвращает обёртку, и хранилище результатов доступно только этой обёртке. Для кэша удобен Map: ключом в нём может быть любое значение, а ключи сравниваются почти как через ===, только NaN считается равным NaN.

// memoize :: (a -> b) -> (a -> b)
// для функций одного аргумента: ключ кэша — сам аргумент
const memoize = (fn) => {
  // кэш в замыкании: снаружи до него не добраться
  const cache = new Map()
  return (arg) => {
    if (cache.has(arg)) {
      return cache.get(arg)
    }
    const result = fn(arg)
    cache.set(arg, result)
    return result
  }
}

// счётчик показывает, сколько раз функция действительно считала;
// это побочный эффект, он здесь только для наглядности
let calls = 0

// countDivisors :: Number -> Number
// перебирает все числа от 1 до n: чем больше n, тем дольше
const countDivisors = (n) => {
  calls += 1
  return R.range(1, n + 1).filter((i) => n % i === 0).length
}

const countDivisorsMemo = memoize(countDivisors)

console.log(countDivisorsMemo(360)) // 24
console.log(countDivisorsMemo(360)) // 24, из кэша
console.log(countDivisorsMemo(1000)) // 16
console.log('вычислений: ' + calls) // вычислений: 2

Мемоизировать можно только чистые функции. Кэш подменяет вызов сохранённым результатом, а это безопасно, только когда функция при одних и тех же аргументах всегда возвращает одно и то же и ничего не меняет снаружи. Если результат зависит от внешней переменной, кэш вернёт устаревшее значение. Если функция что-то записывает или отправляет, при повторных вызовах этого просто не произойдёт.

Ключ кэша

Ключ решает, какие вызовы считать одинаковыми. Для одного аргумента-примитива ключом служит сам аргумент. Объекты Map сравнивает по ссылке: объект с тем же содержимым, но созданный заново, кэш не найдёт, а объект, изменённый на месте, найдёт вместе с устаревшим результатом. Поэтому мемоизация хорошо сочетается с иммутабельными данными из урока «Иммутабельность»: новое значение — новый объект и новый ключ.

// memoize из предыдущего примера
// memoize :: (a -> b) -> (a -> b)
const memoize = (fn) => {
  const cache = new Map()
  return (arg) => {
    if (cache.has(arg)) {
      return cache.get(arg)
    }
    const result = fn(arg)
    cache.set(arg, result)
    return result
  }
}

// === нечистая функция: результат зависит от внешней переменной ===
let rate = 90
// toRub :: Number -> Number
const toRub = (usd) => usd * rate
const toRubMemo = memoize(toRub)

console.log(toRubMemo(10)) // 900
rate = 100
console.log(toRub(10)) // 1000
console.log(toRubMemo(10)) // 900: курс уже другой, а результат из кэша

// === ключ-объект сравнивается по ссылке ===
let lengthCalls = 0
// nameLength :: Object -> Number
const nameLength = memoize((user) => {
  lengthCalls += 1
  return user.name.length
})

const john = { name: 'John' }
console.log(nameLength(john)) // 4
// то же содержимое, но другой объект: кэш не помог
console.log(nameLength({ name: 'John' })) // 4
console.log('вычислений: ' + lengthCalls) // вычислений: 2

// объект изменили на месте, ссылка та же: из кэша приходит старый ответ
john.name = 'Johnny'
console.log(nameLength(john)) // 4, хотя в имени уже 6 букв

В Ramda есть R.memoizeWith(keyFn, fn): первая функция строит ключ из аргументов, вторая считает результат. Кэш внутри — обычный объект, поэтому ключ должен быть строкой. Всё остальное приводится к строке, и любой объект превращается в один и тот же ключ «[object Object]». Если аргументов несколько, ключ собирают с разделителем: без него вызовы (1, 23) и (12, 3) дали бы одну строку «123».

let calls = 0
// area :: (Number, Number) -> Number
const area = (width, height) => {
  calls += 1
  return width * height
}

// ключ из обоих аргументов с разделителем
const areaMemo = R.memoizeWith((width, height) => width + 'x' + height, area)

console.log(areaMemo(2, 3)) // 6
console.log(areaMemo(2, 3)) // 6, из кэша
console.log(areaMemo(3, 2)) // 6, но ключ другой: 3x2
console.log('вычислений: ' + calls) // вычислений: 2

// === ошибка: ключ-объект ===
// R.identity возвращает сам объект, а в строку он превращается в '[object Object]'
const getName = R.memoizeWith(R.identity, (user) => user.name)
console.log(getName({ id: 1, name: 'John' })) // John
console.log(getName({ id: 2, name: 'Anna' })) // John: чужой результат из кэша

// ключ должен быть строкой, которая различает объекты
const getNameById = R.memoizeWith((user) => String(user.id), (user) => user.name)
console.log(getNameById({ id: 1, name: 'John' })) // John
console.log(getNameById({ id: 2, name: 'Anna' })) // Anna

Рекурсия: числа Фибоначчи

Больше всего мемоизация даёт там, где функция много раз вызывается с одними и теми же аргументами. Классический пример — числа Фибоначчи: fib(n) = fib(n - 1) + fib(n - 2). Наивная рекурсия считает одни и те же значения снова и снова, и число вызовов растёт экспоненциально: для fib(20) их 21 891, для fib(30) — уже 2 692 537.

Чтобы мемоизация сработала, рекурсивные вызовы должны идти через мемоизированную версию. Если обернуть готовую функцию снаружи, в кэш попадёт только верхний вызов, а рекурсия внутри пойдёт мимо него.

// memoize :: (a -> b) -> (a -> b)
const memoize = (fn) => {
  const cache = new Map()
  return (arg) => {
    if (cache.has(arg)) {
      return cache.get(arg)
    }
    const result = fn(arg)
    cache.set(arg, result)
    return result
  }
}

// === наивная рекурсия ===
let naiveCalls = 0
// fib :: Number -> Number
const fib = (n) => {
  naiveCalls += 1
  return n < 2 ? n : fib(n - 1) + fib(n - 2)
}

console.log(fib(20)) // 6765
console.log('вызовов: ' + naiveCalls) // вызовов: 21891

// === обёртка снаружи: рекурсия идёт мимо кэша ===
naiveCalls = 0
const fibWrapped = memoize(fib)
console.log(fibWrapped(20)) // 6765
// fib внутри вызывает саму себя, а не fibWrapped
console.log('вызовов: ' + naiveCalls) // вызовов: 21891
// в кэше только верхний вызов: fibWrapped(20)
console.log(fibWrapped(20)) // 6765
console.log('вызовов: ' + naiveCalls) // вызовов: 21891

// === рекурсия через мемоизированную функцию ===
let memoCalls = 0
// fibMemo :: Number -> Number
const fibMemo = memoize((n) => {
  memoCalls += 1
  return n < 2 ? n : fibMemo(n - 1) + fibMemo(n - 2)
})

console.log(fibMemo(20)) // 6765
// каждое n от 0 до 20 считается один раз
console.log('вычислений: ' + memoCalls) // вычислений: 21
console.log(fibMemo(30)) // 832040
// к ним добавились только n от 21 до 30
console.log('вычислений: ' + memoCalls) // вычислений: 31

Цена памяти и инвалидация

Кэш занимает память и сам не очищается. Если аргументы почти не повторяются, например это идентификаторы запросов или текст, который вводит пользователь, кэш растёт с каждым вызовом и ничего не экономит. У R.memoizeWith кэш спрятан в замыкании: ни ограничить, ни очистить его нельзя, можно только создать новую мемоизированную функцию.

Отсюда два приёма. Первый — ограничить размер. Map помнит порядок вставки, поэтому при переполнении можно удалять первую запись, а запись, к которой обратились, переставлять в конец. Получается кэш LRU (least recently used): он вытесняет то, к чему дольше всего не обращались. Второй — инвалидация. Если результат зависит от данных, которые меняются, их версию включают в ключ или сбрасывают кэш целиком. Для ключей-объектов есть WeakMap: запись в нём не мешает сборщику мусора удалить объект, когда на него больше нет других ссылок.

// memoizeLimited :: Number -> (a -> b) -> (a -> b)
// кэш LRU на limit записей с ручным сбросом
const memoizeLimited = (limit) => (fn) => {
  const cache = new Map()
  const memoized = (arg) => {
    if (cache.has(arg)) {
      const value = cache.get(arg)
      // переставляем запись в конец: её использовали последней
      cache.delete(arg)
      cache.set(arg, value)
      return value
    }
    const result = fn(arg)
    cache.set(arg, result)
    if (cache.size > limit) {
      // первая запись в Map — та, к которой дольше всего не обращались
      cache.delete(cache.keys().next().value)
    }
    return result
  }
  // инвалидация: сбросить весь кэш
  memoized.clear = () => cache.clear()
  memoized.size = () => cache.size
  return memoized
}

let calls = 0
// square :: Number -> Number
const square = (n) => {
  calls += 1
  return n * n
}

const squareMemo = memoizeLimited(2)(square)

squareMemo(1) // считаем
squareMemo(2) // считаем
squareMemo(1) // из кэша, 1 теперь самая свежая запись
squareMemo(3) // считаем, кэш переполнен: вытесняется 2
squareMemo(1) // из кэша
squareMemo(2) // 2 вытеснена, считаем заново
console.log('вычислений: ' + calls + ', в кэше: ' + squareMemo.size()) // вычислений: 4, в кэше: 2

squareMemo.clear()
squareMemo(1) // после сброса считаем заново
console.log('вычислений: ' + calls + ', в кэше: ' + squareMemo.size()) // вычислений: 5, в кэше: 1

Мемоизация окупается, когда функция чистая, считает заметно дольше, чем строится ключ и ищется запись, и вызывается с повторяющимися аргументами. Типичные случаи — рекурсия с перекрывающимися подзадачами, разбор и форматирование одних и тех же строк, вычисление производных данных из состояния. Для дешёвых функций вроде сложения кэш только добавит работы и памяти. Как и в уроке «Производительность», выгоду проверяйте измерением, а не по одному запуску: счётчиком вычислений и попаданий в кэш или повторными замерами времени.

Главное

  • Мемоизация запоминает результат функции по её аргументам и при повторном вызове с теми же аргументами возвращает его из кэша, который живёт в замыкании.
  • Мемоизировать можно только чистые функции: иначе кэш вернёт устаревший результат или пропустит побочный эффект.
  • Ключ кэша решает, какие вызовы одинаковы: Map сравнивает объекты по ссылке, R.memoizeWith(keyFn, fn) ждёт ключ-строку, а для нескольких аргументов ключ собирают с разделителем.
  • В рекурсии вызовы должны идти через мемоизированную функцию: fib(20) без кэша делает 21 891 вызов, а с кэшем считает 21 значение.
  • Кэш стоит памяти и сам не очищается: размер ограничивают вытеснением старых записей, а при изменении внешних данных кэш сбрасывают или включают версию данных в ключ.

Упражнение 1

Функция paths(rows, cols) считает, сколькими путями можно пройти из левого верхнего угла сетки в правый нижний, если двигаться только вправо или вниз. Наивная рекурсия для сетки 10 на 10 делает сотни тысяч вызовов. Напишите pathsMemo через R.memoizeWith: рекурсивные вызовы должны идти через кэш, а ключ — различать пары аргументов. Сравните число вызовов и вычислений.

Заготовка

let naiveCalls = 0
// paths :: (Number, Number) -> Number
const paths = (rows, cols) => {
  naiveCalls += 1
  if (rows === 0 || cols === 0) return 1
  return paths(rows - 1, cols) + paths(rows, cols - 1)
}

console.log(paths(10, 10))
console.log('без кэша, вызовов: ' + naiveCalls)

let memoCalls = 0
// ваш код: pathsMemo через R.memoizeWith, внутри увеличивайте memoCalls

console.log(pathsMemo(10, 10))
console.log('с кэшем, вычислений: ' + memoCalls)

let naiveCalls = 0
// paths :: (Number, Number) -> Number
const paths = (rows, cols) => {
  naiveCalls += 1
  if (rows === 0 || cols === 0) return 1
  return paths(rows - 1, cols) + paths(rows, cols - 1)
}

console.log(paths(10, 10))
console.log('без кэша, вызовов: ' + naiveCalls)

let memoCalls = 0
// pathsMemo :: (Number, Number) -> Number
// ключ из обоих аргументов с разделителем, рекурсия идёт через pathsMemo
const pathsMemo = R.memoizeWith(
  (rows, cols) => rows + ',' + cols,

  },
)

// каждая пара (rows, cols) считается один раз
console.log('с кэшем, вычислений: ' + memoCalls)

Упражнение 2

Функция priceWithTax берёт ставку налога в процентах из внешней переменной taxPercent, поэтому мемоизированная версия после смены ставки возвращает старые цены. Сделайте функцию чистой: ставка должна приходить аргументом. Мемоизируйте её через R.memoizeWith так, чтобы ставка входила в ключ. Вызовите priceMemo для цены 100 дважды при ставке 20% и один раз при 10%, выведите все три цены, а затем число вычислений: его считает calls из заготовки.

// memoize для функций одного аргумента
// memoize :: (a -> b) -> (a -> b)
const memoize = (fn) => {
  const cache = new Map()
  return (arg) => {
    if (cache.has(arg)) {
      return cache.get(arg)
    }
    const result = fn(arg)
    cache.set(arg, result)
    return result
  }
}

// счётчик показывает, сколько раз функция действительно считала;
// это побочный эффект, он здесь только для наглядности
let calls = 0

let taxPercent = 20
// priceWithTax :: Number -> Number
const priceWithTax = (price) => {
  calls += 1
  return price + (price * taxPercent) / 100
}
const priceMemo = memoize(priceWithTax)

console.log(priceMemo(100))
taxPercent = 10
// ставка уже 10%, а цена старая
console.log(priceMemo(100))

let calls = 0
