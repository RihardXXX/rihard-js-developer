11 Бесточечный стиль

Цель урока Научиться записывать функции в бесточечном стиле через pipe, compose и каррированные функции, понять, почему ['1', '2', '3'].map(parseInt) даёт [1, NaN, NaN], отлаживать такие конвейеры через tap и видеть, когда явный аргумент читается лучше.

Бесточечный стиль (point-free style, его ещё называют tacit programming) — это способ определить функцию, не упоминая её аргументы. Новая функция собирается из других функций через композицию, каррирование и частичное применение. Вместо «возьми пользователя и верни его имя» мы пишем «это R.prop('name')».

«Точка» здесь — не символ точки в user.name, а аргумент функции. Термин пришёл из математики: в топологии функции действуют на пространства, которые состоят из точек, и бесточечное определение функции не называет точки, то есть значения, к которым она применяется. Поэтому R.prop('name') — бесточечная запись, хотя символ точки в ней есть.

Стиль опирается на то, что мы уже умеем: каррированная функция возвращает новую функцию, пока не получит все аргументы, а pipe и compose собирают функции в конвейер. В Ramda функции каррированы и, как правило, принимают данные последним аргументом, поэтому R.filter(isOnline) — уже готовая функция, которая ждёт список.

// Ramda в песочнице курса доступна как R
const users = [
  { name: 'John', status: 'online', age: 25 },
  { name: 'Alex', status: 'offline', age: 30 },
  { name: 'Angel', status: 'online', age: 16 },
]

// === с «точками»: аргументы названы явно ===
// getNameP :: Object -> String
const getNameP = (user) => user.name
// isOnlineP :: Object -> Boolean
const isOnlineP = (user) => user.status === 'online'
// onlineNamesP :: [Object] -> [String]
const onlineNamesP = (list) => list.filter((user) => isOnlineP(user)).map((user) => getNameP(user))

// === без «точек»: функции собраны из других функций ===
// getName :: Object -> String
const getName = R.prop('name')
// isOnline :: Object -> Boolean
// в современных версиях Ramda propEq принимает сначала значение, потом ключ,
// в старых порядок был обратным
const isOnline = R.propEq('online', 'status')
// onlineNames :: [Object] -> [String]
const onlineNames = R.pipe(R.filter(isOnline), R.map(getName))
// то же через compose: шаги записаны справа налево
const onlineNamesC = R.compose(R.map(getName), R.filter(isOnline))

console.log(onlineNamesP(users).join(', ')) // John, Angel
console.log(onlineNames(users).join(', ')) // John, Angel
console.log(onlineNamesC(users).join(', ')) // John, Angel

// === свои каррированные функции работают так же ===
// add :: Number -> Number -> Number
const add = (a) => (b) => a + b
// с точкой: обёртка только передаёт n дальше
// incP :: Number -> Number
const incP = (n) => add(1)(n)
// без точки: add(1) уже функция, которая ждёт второе число
// inc :: Number -> Number
const inc = add(1)

console.log(incP(41)) // 42
console.log(inc(41)) // 42

Простейший переход к бесточечной записи — убрать обёртку: (x) => f(x) делает то же, что сама f. В этом и главная ловушка стиля. Обёртка передаёт в f ровно один аргумент, а f без обёртки получает всё, что передаст вызывающий код.

Ловушка: лишние аргументы

Array.prototype.map вызывает колбэк с тремя аргументами: элементом, его индексом и всем массивом. parseInt принимает два: строку и основание системы счисления. Поэтому ['1', '2', '3'].map(parseInt) на деле вызывает parseInt('1', 0), parseInt('2', 1) и parseInt('3', 2) и возвращает [1, NaN, NaN].

// map передаёт колбэку элемент, индекс и массив,
// а второй параметр parseInt — основание системы счисления
console.log(['1', '2', '3'].map(parseInt)) // [1, NaN, NaN]

// что на самом деле вызывается
// основание 0 значит «не задано»: строка без префикса 0x читается как десятичное число
console.log(parseInt('1', 0)) // 1
// основание 1 недопустимо: parseInt принимает основания от 2 до 36
console.log(parseInt('2', 1)) // NaN
// в двоичной записи нет цифры 3
console.log(parseInt('3', 2)) // NaN

// === как исправить ===
// Number использует только первый аргумент
// он строже parseInt: Number('12px') — NaN, а parseInt('12px', 10) — 12
console.log(['1', '2', '3'].map(Number)) // [1, 2, 3]
// вернуть «точку» и указать основание явно
console.log(['1', '2', '3'].map((str) => parseInt(str, 10))) // [1, 2, 3]
// R.map передаёт колбэку только элемент
console.log(R.map(parseInt, ['1', '2', '3'])) // [1, 2, 3]
// R.unary оставляет функции один аргумент, остальные отбрасывает
console.log(['1', '2', '3'].map(R.unary(parseInt))) // [1, 2, 3]

Так же ведут себя forEach, filter и другие методы массивов. С методами объектов ловушка другая: arr.map(obj.method) вызовет метод без объекта, и this внутри него будет не тем. Есть и отложенный вариант: если функция, которую передают в map без обёртки, позже получит необязательный второй параметр, в него молча начнёт приходить индекс.

Читаемость и отладка

Бесточечная запись короче, но не всегда понятнее: чтобы её прочитать, нужно помнить сигнатуру каждой функции. R.lte(18) — это функция age => 18 <= age, а R.gt(18) — age => 18 > age. Поэтому R.filter(R.gt(18)) оставляет тех, кто младше 18, хотя читается как «больше 18».

const users = [
  { name: 'John', status: 'online', age: 25 },
  { name: 'Alex', status: 'offline', age: 30 },
  { name: 'Angel', status: 'online', age: 16 },
]

// бесточечно: нужно знать, что R.lte(18) — это age => 18 <= age
// isAdultOnline :: Object -> Boolean
const isAdultOnline = R.both(R.propSatisfies(R.lte(18), 'age'), R.propEq('online', 'status'))

// с точкой: условие видно сразу
// isAdultOnlineP :: Object -> Boolean
const isAdultOnlineP = (user) => user.age >= 18 && user.status === 'online'

console.log(users.filter(isAdultOnline).length) // 1
console.log(users.filter(isAdultOnlineP).length) // 1

// R.gt(18) читается как «больше 18», а означает age => 18 > age
// ages :: [Number]
const ages = [10, 18, 20, 30]
console.log(R.filter(R.gt(18), ages).join(', ')) // 10
// с явным аргументом не ошибёшься
console.log(ages.filter((age) => age > 18).join(', ')) // 20, 30

Вторая цена — отладка. У бесточечной функции нет тела, в него не поставить точку останова или console.log. Сам console.log в конвейер вставлять нельзя: он возвращает undefined, и следующий шаг получит его вместо данных. Выручает tap: она вызывает переданную функцию ради побочного эффекта и возвращает аргумент без изменений. Подробнее о ней — в уроке «Side effects (побочные эффекты) в композиции функций», а в Ramda есть готовая R.tap.

const users = [
  { name: 'John', status: 'online', age: 25 },
  { name: 'Alex', status: 'offline', age: 30 },
  { name: 'Angel', status: 'online', age: 16 },
]

// tap :: (a -> *) -> a -> a
// вызывает fn ради побочного эффекта и возвращает x без изменений
const tap = (fn) => (x) => {
  fn(x)
  return x
}

// log :: String -> a -> a
const log = (label) => tap((value) => console.log(label + ': ' + JSON.stringify(value)))

// onlineNames :: [Object] -> String
const onlineNames = R.pipe(
  R.filter(R.propEq('online', 'status')),
  log('после filter'), // печатает промежуточный результат
  R.map(R.prop('name')),
  log('после map'),
  R.join(', '),
)

console.log(onlineNames(users))
// после filter: [{"name":"John","status":"online","age":25},{"name":"Angel","status":"online","age":16}]
// после map: ["John","Angel"]
// John, Angel

Когда стиль не нужен

Бесточечный стиль — инструмент, а не цель. Он хорош там, где конвейер читается как перечень шагов: «оставить тех, кто в сети, взять имена». Явный аргумент лучше в таких случаях:

  • аргумент нужен в нескольких местах: (user) => user.firstName + ' ' + user.lastName проще, чем та же функция через R.converge;
  • для бесточечной записи приходится переставлять аргументы через R.flip или заполнитель R.__;
  • функция, которую вы передаёте без обёртки, принимает необязательные параметры или зависит от this, как parseInt и методы объектов;
  • имя аргумента объясняет читателю, с какими данными работает функция.

Практическое правило: собирайте конвейер из готовых функций без «точек», а если для этого понадобились flip, converge или заполнители, назовите аргумент.

Главное

  • Бесточечный стиль определяет функцию без упоминания её аргументов: она собирается из других функций через композицию и каррирование, например R.pipe(R.filter(isOnline), R.map(R.prop('name'))).
  • Обёртку (x) => f(x) можно заменить на f, только если f не примет лишних аргументов: ['1', '2', '3'].map(parseInt) даёт [1, NaN, NaN], потому что map передаёт ещё индекс и массив.
  • Ловушку обходят через Number, явную стрелку с основанием, R.map, который передаёт только элемент, или R.unary.
  • Бесточечный конвейер отлаживают через tap: она выполняет побочный эффект и возвращает аргумент без изменений.
  • Если для бесточечной записи нужны flip, converge или заполнители либо имя аргумента что-то объясняет, явный аргумент читается лучше.

Упражнения

Упражнение 1

Перепишите функции getTitleP, isInStockP, toUpperP и availableTitlesP в бесточечном стиле: getTitle, isInStock, toUpper и availableTitles не должны упоминать свои аргументы. Пригодятся R.prop, R.propEq (сначала значение, потом ключ), R.toUpper, R.filter, R.map и R.pipe. Выведите результат обеих версий и убедитесь, что он совпадает.

Заготовка

const products = [
  { title: 'Book', price: 400, inStock: true },
  { title: 'Pen', price: 50, inStock: false },
  { title: 'Lamp', price: 1200, inStock: true },
  { title: 'Mug', price: 300, inStock: true },
]

// версии с «точками»
// getTitleP :: Object -> String
const getTitleP = (product) => product.title
// isInStockP :: Object -> Boolean
const isInStockP = (product) => product.inStock === true
// toUpperP :: String -> String
const toUpperP = (str) => str.toUpperCase()
// availableTitlesP :: [Object] -> [String]
const availableTitlesP = (list) => list.filter((product) => isInStockP(product)).map((product) => toUpperP(getTitleP(product)))

// ваш код: getTitle, isInStock, toUpper, availableTitles

console.log(availableTitlesP(products).join(', '))
console.log(availableTitles(products).join(', '))

Ожидаемый вывод

Показать решение
const products = [
  { title: 'Book', price: 400, inStock: true },
  { title: 'Pen', price: 50, inStock: false },
  { title: 'Lamp', price: 1200, inStock: true },
  { title: 'Mug', price: 300, inStock: true },
]

// версии с «точками»
// getTitleP :: Object -> String
const getTitleP = (product) => product.title
// isInStockP :: Object -> Boolean
const isInStockP = (product) => product.inStock === true
// toUpperP :: String -> String
const toUpperP = (str) => str.toUpperCase()
// availableTitlesP :: [Object] -> [String]
const availableTitlesP = (list) => list.filter((product) => isInStockP(product)).map((product) => toUpperP(getTitleP(product)))

// getTitle :: Object -> String
const getTitle = R.prop('title')
// isInStock :: Object -> Boolean
const isInStock = R.propEq(true, 'inStock')
// метод строки без обёртки не передать: у Ramda есть функция-аналог
// toUpper :: String -> String
const toUpper = R.toUpper
// availableTitles :: [Object] -> [String]
// для каждого товара два шага подряд — это тоже конвейер
const availableTitles = R.pipe(R.filter(isInStock), R.map(R.pipe(getTitle, toUpper)))

console.log(availableTitlesP(products).join(', '))
console.log(availableTitles(products).join(', '))

Упражнение 2

Функция sumCsv должна складывать числа из строки '10,20,30' и печатать 60, а печатает NaN. В заготовке есть tap и логгер log. Соберите отладочную версию sumCsvDebug: тот же конвейер с log после каждого шага. Найдите шаг, на котором портятся данные, объясните причину и исправьте sumCsv так, чтобы она осталась бесточечной. Выведите результат sumCsvDebug('10,20,30'), затем исправленной sumCsv.

Заготовка

// tap :: (a -> *) -> a -> a
const tap = (fn) => (x) => {
  fn(x)
  return x
}
// log :: String -> a -> a
// R.toString показывает NaN, а JSON.stringify превратил бы его в null
const log = (label) => tap((value) => console.log(label + ': ' + R.toString(value)))

// map в духе урока «Каррирование»: передаёт fn в метод массива как есть
// map :: (a -> b) -> [a] -> [b]
const map = (fn) => (arr) => arr.map(fn)
// split :: String -> String -> [String]
const split = (separator) => (str) => str.split(separator)
// sum :: [Number] -> Number
const sum = (arr) => arr.reduce((acc, n) => acc + n, 0)

// sumCsv :: String -> Number
const sumCsv = R.pipe(split(','), map(parseInt), sum)

// ваш код: sumCsvDebug и исправленная sumCsv

console.log(sumCsv('10,20,30'))

Ожидаемый вывод

map: [10, NaN, NaN]
NaN
60
Показать решение
// tap :: (a -> *) -> a -> a
const tap = (fn) => (x) => {
  fn(x)
  return x
}
// log :: String -> a -> a
// R.toString показывает NaN, а JSON.stringify превратил бы его в null
const log = (label) => tap((value) => console.log(label + ': ' + R.toString(value)))

// map в духе урока «Каррирование»: передаёт fn в метод массива как есть
// map :: (a -> b) -> [a] -> [b]
const map = (fn) => (arr) => arr.map(fn)
// split :: String -> String -> [String]
const split = (separator) => (str) => str.split(separator)
// sum :: [Number] -> Number
const sum = (arr) => arr.reduce((acc, n) => acc + n, 0)

// отладочная версия: тот же конвейер, после каждого шага log
const sumCsvDebug = R.pipe(split(','), log('split'), map(parseInt), log('map'), sum)
console.log(sumCsvDebug('10,20,30'))

// после map данные испорчены: метод массива передаёт parseInt ещё и индекс,
// он становится основанием: parseInt('20', 1) и parseInt('30', 2) дают NaN
// Number использует только первый аргумент, и конвейер остаётся бесточечным
// sumCsv :: String -> Number
const sumCsv = R.pipe(split(','), map(Number), sum)

console.log(sumCsv('10,20,30'))
