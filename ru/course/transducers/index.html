17 Трансдьюсеры

Цель урока Понять, почему цепочка map и filter создаёт промежуточные массивы, научиться писать трансдьюсеры как трансформеры редьюсера, композировать их через compose, пользоваться R.transduce и R.into и оценивать, когда это окупается.

Цепочка map и filter читается хорошо, но у неё есть цена. Каждый шаг проходит весь массив и создаёт новый. В filter(isEven), map(square), filter(isBig) три прохода и три новых массива, причём два из них промежуточные: они нужны только как вход для следующего шага. В уроке «Производительность» мы уже считали такие накладные расходы вызовами колбэков, теперь посчитаем и массивы.

// счётчики: сколько массивов создано и сколько раз вызваны шаги
const stats = { arrays: 0, calls: 0 }

// map :: (a -> b) -> [a] -> [b]
const map = (fn) => (arr) => {
  stats.arrays += 1
  return arr.map((x) => {
    stats.calls += 1
    return fn(x)
  })
}
// filter :: (a -> Boolean) -> [a] -> [a]
const filter = (pred) => (arr) => {
  stats.arrays += 1
  return arr.filter((x) => {
    stats.calls += 1
    return pred(x)
  })
}

// isEven :: Number -> Boolean
const isEven = (n) => n % 2 === 0
// square :: Number -> Number
const square = (n) => n * n
// isBig :: Number -> Boolean
const isBig = (n) => n > 100000

// числа от 1 до 1000
const numbers = R.range(1, 1001)

const result = R.pipe(filter(isEven), map(square), filter(isBig))(numbers)

console.log('чисел в результате: ' + result.length) // чисел в результате: 342
// 1000 вызовов первого filter, 500 вызовов map и 500 вызовов второго filter
console.log('массивов: ' + stats.arrays + ', вызовов: ' + stats.calls) // массивов: 3, вызовов: 2000

Можно склеить все шаги в один reduce, как в упражнении урока «Производительность», но тогда они сольются в один колбэк и перестанут быть отдельными функциями. Трансдьюсеры дают и то и другое: шаги остаются отдельными и композируемыми, а данные проходят через них за один проход, без промежуточных массивов. Идея пришла из языка Clojure, где трансдьюсеры предложил Рич Хикки в 2014 году.

Редьюсер и трансформер редьюсера

Редьюсер — функция, которую принимает reduce: (acc, x) => newAcc. Она получает накопленное значение и очередной элемент и возвращает новое накопленное значение. Сумма — редьюсер, добавление элемента в конец массива — тоже редьюсер.

Трансдьюсер — это трансформер редьюсера: функция, которая принимает редьюсер и возвращает новый редьюсер. mapping(f) делает из редьюсера такой, который сначала применяет f к элементу, а filtering(pred) — такой, который пропускает к исходному редьюсеру только подходящие элементы. Ни один из них не знает, что делает редьюсер: копит массив, считает сумму или собирает строку.

// === редьюсеры: (acc, x) -> acc ===
// pushTo :: ([a], a) -> [a]
// меняет только аккумулятор, который мы создали для этой свёртки;
// копия [...acc, x] на каждом шаге дала бы квадратичную работу
const pushTo = (acc, x) => {
  acc.push(x)
  return acc
}
// sum :: (Number, Number) -> Number
const sum = (acc, x) => acc + x

// === трансдьюсеры: принимают редьюсер и возвращают редьюсер ===
// mapping :: (a -> b) -> ((acc, b) -> acc) -> ((acc, a) -> acc)
const mapping = (fn) => (reducer) => (acc, x) => reducer(acc, fn(x))
// filtering :: (a -> Boolean) -> ((acc, a) -> acc) -> ((acc, a) -> acc)
const filtering = (pred) => (reducer) => (acc, x) => (pred(x) ? reducer(acc, x) : acc)

// isEven :: Number -> Boolean
const isEven = (n) => n % 2 === 0
// square :: Number -> Number
const square = (n) => n * n

// вручную: mapping оборачивает pushTo, filtering оборачивает то, что получилось
const evenSquaresToArray = filtering(isEven)(mapping(square)(pushTo))
console.log([1, 2, 3, 4, 5, 6].reduce(evenSquaresToArray, []).join(', ')) // 4, 16, 36

// те же шаги с другим редьюсером: сумма вместо массива
const evenSquaresSum = filtering(isEven)(mapping(square)(sum))
console.log([1, 2, 3, 4, 5, 6].reduce(evenSquaresSum, 0)) // 56

Композиция трансдьюсеров

Трансдьюсер — функция одного аргумента, поэтому трансдьюсеры композируются через compose. Порядок записи здесь непривычный: в compose(filtering(isEven), mapping(square)) элементы сначала фильтруются и только потом возводятся в квадрат. Шаги выполняются слева направо, как в pipe.

Почему так. compose действительно применяет функции справа налево, но применяет их к редьюсеру, а не к данным. Сначала mapping(square) оборачивает конечный редьюсер, затем filtering(isEven) оборачивает то, что получилось. Самая левая обёртка оказывается внешней, и каждый элемент первым попадает именно в неё. Обёртки строятся справа налево, а данные проходят через них слева направо.

// compose :: ((y -> z), ..., (a -> b)) -> a -> z
const compose = (...fns) => (x) => fns.reduceRight((acc, fn) => fn(acc), x)

// transduce :: (трансдьюсер, редьюсер, acc, [a]) -> acc
const transduce = (xform, reducer, init, arr) => arr.reduce(xform(reducer), init)

// mapping и filtering из предыдущего примера
const mapping = (fn) => (reducer) => (acc, x) => reducer(acc, fn(x))
const filtering = (pred) => (reducer) => (acc, x) => (pred(x) ? reducer(acc, x) : acc)

// счётчики: массивы создаём только через newArray, шаги считает counted
const stats = { arrays: 0, calls: 0 }
const newArray = () => {
  stats.arrays += 1
  return []
}
const counted = (fn) => (x) => {
  stats.calls += 1
  return fn(x)
}

const pushTo = (acc, x) => {
  acc.push(x)
  return acc
}
const isEven = (n) => n % 2 === 0
const square = (n) => n * n
const isBig = (n) => n > 100000

// шаги записаны в порядке выполнения: filter, map, filter
const xform = compose(
  filtering(counted(isEven)),
  mapping(counted(square)),
  filtering(counted(isBig)),
)

const result = transduce(xform, pushTo, newArray(), R.range(1, 1001))

console.log('чисел в результате: ' + result.length) // чисел в результате: 342
// один проход, один массив — аккумулятор, а вызовов шагов столько же, сколько в цепочке
console.log('массивов: ' + stats.arrays + ', вызовов: ' + stats.calls) // массивов: 1, вызовов: 2000

Трансдьюсеры в Ramda

В Ramda map, filter, take и ряд других функций списков работают как трансдьюсеры, если вызвать их без данных и передать результат в R.transduce или R.into. R.transduce(xform, reducer, init, list) — свёртка, как наша transduce: редьюсер и начальное значение задаёте вы. R.into(acc, xform, list) выбирает редьюсер по первому аргументу: в массив элементы добавляются, к строке приписываются, а в объект копируются их свойства или пары [ключ, значение]. При этом в Ramda 0.32 от первого аргумента берётся только тип, а его содержимое в результат не попадает: R.into([1, 2], R.map(R.inc), [3]) вернёт [4], а не [1, 2, 4]. Поэтому передавайте пустое значение: [], '' или {}. В документации Ramda трансформером называют объект с методами @@transducer/init, @@transducer/step и @@transducer/result, а трансдьюсером — функцию, которая принимает такой трансформер и возвращает новый. Идея та же, только вместо функции-редьюсера объект.

// isEven :: Number -> Boolean
const isEven = (n) => n % 2 === 0
// числа от 1 до 10
const numbers = R.range(1, 11)

// R.filter и R.map без данных — трансдьюсеры
const xform = R.compose(R.filter(isEven), R.map((n) => n * n))

// R.into: результат той же формы, что и первый аргумент
console.log(R.into([], xform, numbers).join(', ')) // 4, 16, 36, 64, 100
console.log(R.into('', R.compose(xform, R.map((n) => n + ';')), numbers)) // 4;16;36;64;100;
// R.transduce: свой редьюсер и начальное значение
console.log(R.transduce(xform, R.add, 0, numbers)) // 220

// === одна композиция, два порядка ===
const incThenKeepEven = R.compose(R.map(R.inc), R.filter(isEven))
// как обычная функция на массиве: compose справа налево — сначала filter, потом map
console.log(incThenKeepEven([1, 2, 3, 4]).join(', ')) // 3, 5
// как трансдьюсер: слева направо — сначала map, потом filter
console.log(R.into([], incThenKeepEven, [1, 2, 3, 4]).join(', ')) // 2, 4

// === ранняя остановка ===
let chainCalls = 0
const chainResult = R.range(1, 1001)
  .map((n) => {
    chainCalls += 1
    return n * n
  })
  .filter((n) => n > 100)
  .slice(0, 3)
console.log(chainResult.join(', ') + ', вызовов map: ' + chainCalls) // 121, 144, 169, вызовов map: 1000

let xformCalls = 0
const firstThree = R.compose(
  R.map((n) => {
    xformCalls += 1
    return n * n
  }),
  R.filter((n) => n > 100),
  R.take(3), // набрал три элемента — свёртка останавливается
)
console.log(R.into([], firstThree, R.range(1, 1001)).join(', ') + ', вызовов map: ' + xformCalls) // 121, 144, 169, вызовов map: 13

Когда это окупается

При полном проходе трансдьюсеры не уменьшают число вызовов шагов: каждый элемент проходит через каждый шаг, до которого дошёл, как и в цепочке. Выигрыш в другом. Нет промежуточных массивов и лишних проходов. Свёртку можно остановить раньше, как с R.take. Один и тот же трансформ работает с любым редьюсером и с любым источником, который понимает свёртка Ramda: массивом, итерируемым объектом вроде Set или генератора, объектом с методом reduce.

Это заметно на больших коллекциях, длинных цепочках и при ранней остановке. Для массива из сотни элементов и двух шагов цепочка map и filter проще читается и работает достаточно быстро. В ES2025 у итераторов появились свои ленивые методы map, filter и take: они тоже обрабатывают элементы по одному, без промежуточных массивов. Трансдьюсеры отличаются тем, что отделяют преобразование и от источника данных, и от способа собрать результат. Выгоду, как и в уроке «Производительность», проверяйте измерением: счётчиком массивов и вызовов или повторными замерами, а не одним запуском.

Главное

  • Каждый шаг цепочки map и filter проходит массив целиком и создаёт новый массив; промежуточные массивы нужны только как вход для следующего шага.
  • Редьюсер — функция (acc, x) => acc, а трансдьюсер — трансформер редьюсера: он принимает редьюсер и возвращает новый, не зная, что тот собирает.
  • compose применяет трансдьюсеры к редьюсеру справа налево, поэтому самая левая обёртка оказывается внешней и данные проходят шаги слева направо.
  • В Ramda map, filter и take без данных работают как трансдьюсеры: R.transduce сворачивает с вашим редьюсером, R.into собирает результат в массив, строку или объект.
  • Трансдьюсеры убирают промежуточные массивы и лишние проходы и умеют останавливаться раньше; на маленьких массивах и коротких цепочках обычная цепочка проще.

Упражнения

Упражнение 1

Напишите трансдьюсеры mapping и filtering и соберите из них через compose трансдьюсер paidTotals: оставить оплаченные заказы, взять их сумму total, оставить суммы от 1000. Примените его к двум редьюсерам из заготовки: с pushTo получится массив сумм, с sum — их итог. Подумайте, в каком порядке записать шаги в compose.

Заготовка

const orders = [
  { id: 1, total: 1200, paid: true },
  { id: 2, total: 300, paid: false },
  { id: 3, total: 4500, paid: true },
  { id: 4, total: 800, paid: true },
  { id: 5, total: 2500, paid: false },
]

// compose :: ((y -> z), ..., (a -> b)) -> a -> z
const compose = (...fns) => (x) => fns.reduceRight((acc, fn) => fn(acc), x)

// редьюсеры
// pushTo :: ([a], a) -> [a]
const pushTo = (acc, x) => {
  acc.push(x)
  return acc
}
// sum :: (Number, Number) -> Number
const sum = (acc, x) => acc + x

// ваш код: mapping, filtering и paidTotals

console.log(orders.reduce(paidTotals(pushTo), []).join(', '))
console.log(orders.reduce(paidTotals(sum), 0))

Ожидаемый вывод

1200, 4500
5700
Показать решение
const orders = [
  { id: 1, total: 1200, paid: true },
  { id: 2, total: 300, paid: false },
  { id: 3, total: 4500, paid: true },
  { id: 4, total: 800, paid: true },
  { id: 5, total: 2500, paid: false },
]

// compose :: ((y -> z), ..., (a -> b)) -> a -> z
const compose = (...fns) => (x) => fns.reduceRight((acc, fn) => fn(acc), x)

// редьюсеры
// pushTo :: ([a], a) -> [a]
const pushTo = (acc, x) => {
  acc.push(x)
  return acc
}
// sum :: (Number, Number) -> Number
const sum = (acc, x) => acc + x

// mapping :: (a -> b) -> ((acc, b) -> acc) -> ((acc, a) -> acc)
const mapping = (fn) => (reducer) => (acc, x) => reducer(acc, fn(x))
// filtering :: (a -> Boolean) -> ((acc, a) -> acc) -> ((acc, a) -> acc)
const filtering = (pred) => (reducer) => (acc, x) => (pred(x) ? reducer(acc, x) : acc)

// шаги записаны в порядке выполнения: самая левая обёртка внешняя,
// поэтому заказ сначала проверяется на оплату, потом превращается в сумму
const paidTotals = compose(
  filtering((order) => order.paid),
  mapping((order) => order.total),
  filtering((total) => total >= 1000),
)

console.log(orders.reduce(paidTotals(pushTo), []).join(', '))
console.log(orders.reduce(paidTotals(sum), 0))

const users = R.range(1, 1001).map((id) => ({ id, name: 'user' + id, active: id % 7 === 0 }))
