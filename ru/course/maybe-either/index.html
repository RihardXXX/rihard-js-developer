23 Maybe и Either

Цель урока Научиться обходиться без null-проверок и try/catch в конвейере: Maybe из Sanctuary — для значения, которого может не быть, Either — для ошибки с причиной; понять, когда шагу нужен map, а когда chain.

В JS отсутствие значения обычно выражают через null и undefined, а ошибку — через исключение. Оба способа плохо сочетаются с конвейером из урока «Композиция функций»: обращение к свойству undefined бросает TypeError, а исключение выходит из середины цепочки и пропускает остальные шаги. По сигнатуре cityOf :: Object -> String не видно, что функция может упасть.

// Проблема: значения может не быть
const users = [
  { name: 'Ann', address: { city: 'Riga' } },
  { name: 'Bob' }, // адреса нет
]

// cityOf :: Object -> String
const cityOf = (user) => user.address.city

console.log(cityOf(users[0])) // Riga

try {
  cityOf(users[1]) // у Bob нет address: читаем city у undefined
} catch (error) {
  console.log(error.name) // TypeError
}

// ?. спасает от падения здесь, но undefined уходит дальше
const city = users[1].address?.city
console.log(city) // undefined

try {
  city.toUpperCase() // и программа падает уже в другом месте
} catch (error) {
  console.log(error.name) // TypeError
}

// исключение по сигнатуре тоже не видно: JSON.parse бросает на некорректной строке
try {
  JSON.parse('{ name: Ann }')
} catch (error) {
  console.log(error.name) // SyntaxError
}

Опциональная цепочка ?. спасает от падения в одном месте, но undefined уходит дальше и ломает программу там, где его не ждут. Проверки вида if (user && user.address) работают, но расползаются по коду, и одну из них легко забыть. Нужен способ сделать отсутствие значения и ошибку частью результата, чтобы о них было трудно забыть.

Maybe делает отсутствие значения частью типа: значение Maybe a — это либо Just (значение), либо Nothing. Вы его уже встречали: в уроке «Функциональное программирование» S.head вернул Maybe, а в уроке «Функтор и его законы» мы написали Maybe-подобный контейнер сами. В Sanctuary есть готовый: S.Just, S.Nothing и функции для работы с ними. Maybe — функтор: S.map применяет функцию только к Just, а Nothing проходит дальше без изменений.

// Maybe a: Just (значение) или Nothing
// Sanctuary в песочнице подключена как S

console.log(S.Just(42)) // Just (42)
console.log(S.Nothing) // Nothing

// head :: [a] -> Maybe a — первого элемента может не быть
console.log(S.head(['Riga', 'Oslo'])) // Just ("Riga")
console.log(S.head([])) // Nothing

// map :: (a -> b) -> Maybe a -> Maybe b
// функция применяется только к Just
const shout = (text) => text.toUpperCase()
console.log(S.map(shout)(S.head(['Riga']))) // Just ("RIGA")
console.log(S.map(shout)(S.head([]))) // Nothing, shout не вызывалась

// значение достают один раз, на выходе
// fromMaybe :: a -> Maybe a -> a
console.log(S.fromMaybe('нет города')(S.head([]))) // нет города
// maybe :: b -> (a -> b) -> Maybe a -> b — map и fromMaybe за один шаг
console.log(S.maybe('нет города')(shout)(S.head(['Oslo']))) // OSLO

Достают значение из Maybe один раз, на выходе из конвейера: S.fromMaybe подставляет запасное значение для Nothing, а S.maybe ещё и применяет функцию к значению из Just — это map и fromMaybe за один шаг. Внутри конвейера значение остаётся в Maybe, и каждый шаг пишется так, будто оно точно есть.

map и chain

Если функция возвращает обычное значение, нужен map. Если она сама возвращает Maybe, как S.head или S.get, map даст Maybe внутри Maybe: Just (Just ("Riga")). Для таких функций есть chain :: (a -> Maybe b) -> Maybe a -> Maybe b: он применяет функцию и снимает лишний слой, а для Nothing ничего не делает. Правило простое: функция возвращает значение — map, возвращает Maybe — chain.

// Безопасное чтение вложенных данных

// isObject :: * -> Boolean
const isObject = (x) => typeof x === 'object' && x !== null
// isString :: * -> Boolean
const isString = (x) => typeof x === 'string'

// get :: (* -> Boolean) -> String -> a -> Maybe b
// Just, если свойство есть и его значение проходит предикат, иначе Nothing
const getAddress = S.get(isObject)('address')
const getCity = S.get(isString)('city')

const ann = { name: 'Ann', address: { city: 'Riga' } }
const bob = { name: 'Bob' }

// map: getCity возвращает Maybe, и получается Maybe внутри Maybe
console.log(S.map(getCity)(getAddress(ann))) // Just (Just ("Riga"))
// chain :: (a -> Maybe b) -> Maybe a -> Maybe b — применяет и снимает лишний слой
console.log(S.chain(getCity)(getAddress(ann))) // Just ("Riga")
console.log(S.chain(getCity)(getAddress(bob))) // Nothing

// cityName :: a -> String
const cityName = S.pipe([
  getAddress, // Maybe Object
  S.chain(getCity), // getCity возвращает Maybe — chain
  S.map((city) => city.toUpperCase()), // toUpperCase возвращает строку — map
  S.fromMaybe('город не указан'),
])

console.log(cityName(ann)) // RIGA
console.log(cityName(bob)) // город не указан
console.log(cityName({ address: { city: null } })) // город не указан
console.log(cityName(null)) // город не указан

// для пути целиком есть S.gets
console.log(S.gets(isString)(['address', 'city'])(ann)) // Just ("Riga")

// осторожно: S.prop — для объектов, у которых свойство точно есть
try {
  S.prop('address')(bob)
} catch (error) {
  console.log(error.name) // TypeError: свойства нет
}

// и предикат в S.get — не формальность: S.get находит и свойства прототипа
console.log(S.isJust(S.get(() => true)('toString')(bob))) // true
console.log(S.get(isString)('toString')(bob)) // Nothing

S.get принимает предикат, имя свойства и объект и возвращает Just, только если свойство есть и значение проходит предикат. Предикат — не формальность: S.get находит и свойства прототипа, и значение null, поэтому проверяйте тип значения. S.prop возвращает значение без Maybe и бросает TypeError, если свойства нет: он подходит для объектов, у которых свойство точно есть.

Тип с методами chain и of, которые выполняют свои законы, называют монадой; of кладёт значение в контейнер, у Maybe это S.Just. Maybe — монада, та самая, в которую урок «Функциональное программирование» советовал обернуть данные, чтобы композиция не падала. На схеме из урока «Fantasy-land» Monad стоит под Applicative и Chain.

Either: ошибка с причиной

Maybe говорит, что значения нет, но не говорит почему. Either a b хранит либо Left с причиной ошибки, либо Right с результатом (right — «правильный»). S.map и S.chain работают с Right, а Left проходит мимо них без изменений, как Nothing. На выходе S.either принимает две функции — для Left и для Right.

S.encase превращает функцию, которая бросает исключение, в функцию, которая возвращает Either: Right с результатом или Left с пойманной ошибкой. S.maybeToEither даёт отсутствию причину: Nothing становится Left с переданным значением, Just — Right. S.mapLeft меняет причину ошибки и не трогает Right.

// Either a b: Left (причина ошибки) или Right (результат)
// Разбор ввода: строка -> JSON -> поле age -> проверка диапазона

// isNumber :: * -> Boolean
const isNumber = (x) => typeof x === 'number'

// encase :: (a -> b) -> a -> Either e b — e: то, что бросила функция
// mapLeft :: (e -> c) -> Either e b -> Either c b
// текст ошибки JSON.parse в разных браузерах разный, поэтому берём только имя
// parseJson :: String -> Either String *
const parseJson = (text) =>
  S.mapLeft((error) => `не JSON: ${error.name}`)(S.encase(JSON.parse)(text))

// maybeToEither :: a -> Maybe b -> Either a b
// getAge :: * -> Either String Number
const getAge = (data) => S.maybeToEither('нет числового поля age')(S.get(isNumber)('age')(data))

// checkRange :: Number -> Either String Number
const checkRange = (age) =>
  age >= 0 && age <= 150 ? S.Right(age) : S.Left(`возраст вне диапазона: ${age}`)

// readAge :: String -> Either String Number
const readAge = S.pipe([
  parseJson,
  S.chain(getAge), // каждый шаг возвращает Either — chain
  S.chain(checkRange),
])

console.log(readAge('{"age": 30}')) // Right (30)
console.log(readAge('{"age": 200}')) // Left ("возраст вне диапазона: 200")

// either :: (a -> c) -> (b -> c) -> Either a b -> c
// report :: Either String Number -> String
const report = S.either((reason) => `Неверный ввод — ${reason}`)((age) => `Возраст: ${age}`)

const inputs = ['{"age": 30}', '{ age: 30 }', '{"name": "Ann"}', '{"age": 200}', 'null']
inputs.forEach((input) => console.log(report(readAge(input))))
// Возраст: 30
// Неверный ввод — не JSON: SyntaxError
// Неверный ввод — нет числового поля age
// Неверный ввод — возраст вне диапазона: 200
// Неверный ввод — нет числового поля age

Когда что выбирать. Maybe — когда отсутствие значения нормально и причина очевидна: поиск, первый элемент, необязательное поле. Either — когда вызывающему коду нужно знать, что пошло не так: разбор и проверка ввода, бизнес-правила, сообщения пользователю. В обоих случаях отсутствие и ошибка становятся обычными значениями: их видно в сигнатуре, их можно передать дальше и показать, а не ловить через try/catch где-то выше по стеку.

Главное

  • Maybe a — Just (значение) или Nothing. Отсутствие значения становится частью типа вместо null и undefined, а значение достают один раз на выходе через S.fromMaybe или S.maybe.
  • Функция возвращает обычное значение — S.map, возвращает Maybe или Either — S.chain: он применяет функцию и снимает лишний слой.
  • S.get(предикат)(имя)(объект) читает свойство безопасно и проверяет тип значения, а S.prop бросает TypeError, если свойства нет.
  • Either a b — Left (причина ошибки) или Right (результат). S.encase превращает исключение в Left, S.maybeToEither даёт причину отсутствию, S.either обрабатывает оба случая на выходе.
  • Maybe — когда причина отсутствия очевидна, Either — когда вызывающему коду нужно знать, что пошло не так.

Упражнения

Упражнение 1

Напишите firstTag: она возвращает первый тег первой статьи автора с решёткой впереди, а если статей или тегов нет — строку «без тегов». Поле posts может отсутствовать, массивы posts и tags могут быть пустыми. Соберите конвейер из S.get, S.head, S.chain, S.map и S.fromMaybe и решите для каждого шага, нужен ли ему map или chain.

Заготовка

const authors = [
  { name: 'Ann', posts: [{ title: 'Functors', tags: ['fp', 'js'] }] },
  { name: 'Bob', posts: [] },
  { name: 'Eve' },
  { name: 'Max', posts: [{ title: 'Draft', tags: [] }] },
]

// isArray :: * -> Boolean
const isArray = (x) => Array.isArray(x)

// firstTag :: Object -> String
// ваш код

authors.forEach((author) => console.log(`${author.name}: ${firstTag(author)}`))

Ожидаемый вывод

Ann: #fp
Bob: без тегов
Eve: без тегов
Max: без тегов
Показать решение
const authors = [
  { name: 'Ann', posts: [{ title: 'Functors', tags: ['fp', 'js'] }] },
  { name: 'Bob', posts: [] },
  { name: 'Eve' },
  { name: 'Max', posts: [{ title: 'Draft', tags: [] }] },
]

// isArray :: * -> Boolean
const isArray = (x) => Array.isArray(x)

// firstTag :: Object -> String
const firstTag = S.pipe([
  S.get(isArray)('posts'), // Maybe [Object]
  S.chain(S.head), // S.head возвращает Maybe — chain
  S.chain(S.get(isArray)('tags')), // S.get тоже возвращает Maybe — chain
  S.chain(S.head), // Maybe String
  S.map((tag) => `#${tag}`), // обычная функция — map
  S.fromMaybe('без тегов'),
])

authors.forEach((author) => console.log(`${author.name}: ${firstTag(author)}`))

Упражнение 2

Порт в форме настроек приходит строкой. Напишите parsePort :: String -> Either String Number: если строка не целое число, верните Left с причиной «не целое число», если число вне диапазона 1–65535 — Left с причиной «вне диапазона 1–65535», иначе Right (порт). S.parseInt(10)(text) возвращает Just (целое число) или Nothing. Используйте S.maybeToEither и S.chain, а строку для каждого ввода соберите в describe через S.either.

Заготовка

// parsePort :: String -> Either String Number
// ваш код

// describe :: Either String Number -> String
// ваш код

const inputs = ['8080', 'http', '70000', '443']
inputs.forEach((input) => console.log(`${input}: ${describe(parsePort(input))}`))

Ожидаемый вывод

8080: порт 8080
http: ошибка — не целое число
70000: ошибка — вне диапазона 1–65535
443: порт 443
Показать решение
// checkRange :: Number -> Either String Number
const checkRange = (port) =>
  port >= 1 && port <= 65535 ? S.Right(port) : S.Left('вне диапазона 1–65535')

// parsePort :: String -> Either String Number
const parsePort = S.pipe([
  S.parseInt(10), // Maybe Number
  S.maybeToEither('не целое число'), // Nothing становится Left с причиной
  S.chain(checkRange), // checkRange возвращает Either — chain
])

// describe :: Either String Number -> String
const describe = S.either((reason) => `ошибка — ${reason}`)((port) => `порт ${port}`)

const inputs = ['8080', 'http', '70000', '443']
inputs.forEach((input) => console.log(`${input}: ${describe(parsePort(input))}`))
