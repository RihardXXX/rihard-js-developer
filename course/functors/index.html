21 Functors and their laws

Lesson goal Understand what a functor is, a container whose map changes the values and keeps the structure, learn to check the identity and composition laws in code and rely on them when refactoring.

In the lesson "The map, filter, and reduce functions", map worked with arrays, and in the "Hindley–Milner type notation" lesson we came across the signature map :: Functor f => (a -> b) -> f a -> f b. Instead of an array it has f, which stands for any functor. Let's find out what this f is and why map can be trusted.

A functor is a container that has map. map takes an ordinary function a -> b, applies it to the values inside the container and returns a new container of the same kind. The key property of map is that it keeps the structure: an array of three elements becomes an array of three elements in the same order, and only the values themselves change. The original container stays as it was.

// An array is the most familiar functor
// map :: (a -> b) -> [a] -> [b]
const words = ['functor', 'map', 'law']
const lengths = words.map((word) => word.length)

console.log(JSON.stringify(lengths)) // [7,3,3]
// the structure is the same: three elements in the same order, only the values changed
console.log(words.length === lengths.length) // true
// the original array has not changed
console.log(JSON.stringify(words)) // ["functor","map","law"]

// Box is the simplest functor: a container for exactly one value
// Box :: a -> Box a
const Box = (value) => ({
  value,
  // map :: Box a ~> (a -> b) -> Box b
  map: (fn) => Box(fn(value)),
})

const box = Box('functor')
  .map((word) => word.toUpperCase())
  .map((word) => word.length)
console.log(box.value) // 7

// the same function works with any functor: it knows nothing about the container
// double :: Number -> Number
const double = (x) => x * 2
console.log(JSON.stringify([1, 2, 3].map(double))) // [2,4,6]
console.log(Box(21).map(double).value) // 42

// R.map accepts any functor: if the object has a map method, R.map calls it
console.log(R.map(double, Box(21)).value) // 42

Box is useless on its own, but it shows that map is not only about arrays. The double function knows nothing about the container, and it is the container's own map that decides how to reach the values: for an array, visit every element; for Box, take the single value. That is why R.map from Ramda works with both an array and a Box.

A more interesting container is one that may hold no value at all. Just holds a value, Nothing means it is absent. map on Just applies the function, while map on Nothing does nothing: there is nothing to apply the function to. The check for absence lives in one place, in map, and the functions in the chain work with ordinary values. The structure is kept here too: Just stays Just after map, and Nothing stays Nothing. The ready-made Maybe from the Sanctuary library is covered in the "Maybe and Either" lesson.

// A Maybe-like container: there is a value (Just) or there is none (Nothing)

// Just :: a -> Maybe a
const Just = (value) => ({
  // apply the function and put the result back into Just
  map: (fn) => Just(fn(value)),
  // getOrElse :: Maybe a ~> a -> a
  getOrElse: () => value,
})

// Nothing :: Maybe a
const Nothing = {
  // there is nothing to apply the function to: Nothing stays Nothing
  map: () => Nothing,
  getOrElse: (fallback) => fallback,
}

const users = [
  { id: 1, name: 'ann' },
  { id: 2, name: 'bob' },
]

// findUser :: Number -> Maybe Object
const findUser = (id) => {
  const user = users.find((u) => u.id === id)
  return user === undefined ? Nothing : Just(user)
}

// greet :: Number -> String
// the functions in the chain don't check whether the user was found: map does that
const greet = (id) =>
  findUser(id)
    .map((user) => user.name)
    .map((name) => name.toUpperCase())
    .map((name) => `Hello, ${name}`)
    .getOrElse('User not found')

console.log(greet(2)) // Hello, BOB
console.log(greet(7)) // User not found

The functor laws

A map method alone is not enough to make a container a functor: map must obey two laws. Identity: u.map(x => x) is equivalent to u, so if the function changes nothing, map changes nothing either. Composition: u.map(x => f(g(x))) is equivalent to u.map(g).map(f), so one pass with the composition gives the same as two passes in a row. In the notation from the "Category theory" lesson, where the dot means composition, they are written more briefly: map(id) = id and map(f . g) = map(f) . map(g).

// The functor laws on an array and on Box
// identity:    u.map(x => x) is equivalent to u
// composition: u.map(x => f(g(x))) is equivalent to u.map(g).map(f)

// id :: a -> a
const id = (x) => x
// compose :: ((b -> c), (a -> b)) -> a -> c
const compose = (f, g) => (x) => f(g(x))
// "equivalent" means the same structure and the same values
// same :: (a, a) -> Boolean
const same = (a, b) => JSON.stringify(a) === JSON.stringify(b)

const inc = (x) => x + 1
const tenTimes = (x) => x * 10
const u = [1, 2, 3]

console.log(u.map(id) === u) // false: map returned a new array
console.log(same(u.map(id), u)) // true: identity holds
console.log(same(u.map(compose(tenTimes, inc)), u.map(inc).map(tenTimes))) // true: so does composition

// Box from the first example
// Box :: a -> Box a
const Box = (value) => ({
  value,
  map: (fn) => Box(fn(value)),
})

// the laws hold for Box too: we compare the values inside
console.log(Box(5).map(id).value === Box(5).value) // true: identity
console.log(Box(5).map(compose(tenTimes, inc)).value === Box(5).map(inc).map(tenTimes).value) // true: composition

// A "convenient" map that also throws away empty results
// compactMap :: (a -> b) -> [a] -> [b]
const compactMap = (fn) => (arr) => arr.map(fn).filter((x) => x != null)

// identity is broken: there were three elements, now there are two, and 30 moved from index 2 to 1
const scores = [10, null, 30]
console.log(JSON.stringify(compactMap(id)(scores))) // [10,30]
console.log(same(compactMap(id)(scores), scores)) // false

// composition is broken too: two passes can no longer be merged into one
const hideBig = (x) => (x > 15 ? null : x) // hide the big values
const orZero = (x) => (x == null ? 0 : x) // replace an empty value with zero
const values = [10, 30]
console.log(JSON.stringify(compactMap(compose(orZero, hideBig))(values))) // [10,0]
console.log(JSON.stringify(compactMap(orZero)(compactMap(hideBig)(values)))) // [10]

"Equivalent" means the same structure and the same values, not the same object: map always returns a new container, so u.map(id) === u gives false. The laws guarantee that map changes the values and nothing else: it does not throw elements away, does not reorder them and does not change the shape of the container. compactMap breaks both laws, and code that relies on the array length or on indexes breaks after such a map.

Laws and refactoring

The composition law is a refactoring rule: map(f) . map(g) = map(f . g). A chain of two maps can be merged into one pass without an intermediate array, and a long function inside map can be split into several maps. The result will not change, and there is no need to check it on every example: the law guarantees it. With compactMap this is not possible, as the example above showed.

// The composition law as a refactoring rule:
// map(f) . map(g) = map(f . g)

const orders = [
  { id: 1, total: 1200 },
  { id: 2, total: 450 },
  { id: 3, total: 3100 },
]

// a call journal: the order in which the functions run
let journal = []
// traced :: (String, (a -> b)) -> a -> b
const traced = (name, fn) => (x) => {
  journal.push(name)
  return fn(x)
}

// getTotal :: Object -> Number
const getTotal = traced('getTotal', (order) => order.total)
// format :: Number -> String
const format = traced('format', (total) => total.toFixed(2))

// two passes: two traversals and an intermediate array of totals
const twoPasses = R.map(format, R.map(getTotal, orders))
console.log(journal.join(' '))
// getTotal getTotal getTotal format format format

journal = []
// one pass: the composition inside map; R.compose runs the functions right to left
const onePass = R.map(R.compose(format, getTotal), orders)
console.log(journal.join(' '))
// getTotal format getTotal format getTotal format

// the result is the same
console.log(JSON.stringify(onePass)) // ["1200.00","450.00","3100.00"]
console.log(R.equals(twoPasses, onePass)) // true

Look at the journal: the result is the same, but the order of calls is different. With two passes, every getTotal runs first and then every format, while one pass interleaves them. For pure functions the order does not matter, as the "Pure functions" lesson explains. But if the functions write to a log or change outside data, after such a refactoring the effects will happen in a different order.

A promise's then method looks like map: it applies the function to the value once the value arrives and returns a new promise. But a promise is not a strict functor. If the function returns a promise, or any other object with a then method, then does not put it inside but unwraps it and waits for its value. There is no such thing as a promise inside a promise, and the composition law is broken. That is why libraries that follow the laws strictly, Sanctuary for example, do not treat a promise as a functor: S.map does not work with it.

// a promise's then looks like map: it applies the function to the value inside
Promise.resolve(21)
  .then((x) => x * 2)
  .then((x) => console.log(x)) // 42

// but then unwraps the promise that the function returned
// f :: a -> Promise a
const f = (x) => Promise.resolve(x)
// g :: a -> Boolean, whether a promise came in
const g = (value) => value instanceof Promise

const p = Promise.resolve(1)
Promise.all([
  p.then(f).then(g), // then unwrapped the promise from f, so g got 1
  p.then((x) => g(f(x))), // and here g got the promise itself
]).then(([twoThens, composed]) => {
  console.log(twoThens) // false
  console.log(composed) // true
  // the results differ: the composition law does not hold for then
})

The name "functor" comes from category theory. In the "Category theory" lesson a category is types as objects and functions as morphisms between them. A functor maps one category to another: it assigns to each type a a type F a (to the type Number, the type [Number]), and to each function f :: a -> b a function map(f) :: F a -> F b. The functor laws say exactly that this mapping preserves identity morphisms and composition. In programming a functor takes the language's types to types of the same language, which is why it is called an endofunctor. This is an idealization: it holds for pure functions that finish without exceptions.

Key points

  • A functor is a container with map: map applies a function to the values inside and returns a new container with the same structure. An array, Box and a Maybe-like container are functors.
  • The functor laws: identity, where u.map(x => x) is equivalent to u, and composition, where u.map(x => f(g(x))) is equivalent to u.map(g).map(f). A map method without the laws does not make a container a functor.
  • The composition law is a refactoring rule: map(f) . map(g) = map(f . g). Two passes can be merged into one: the result stays the same but the order of calls changes, so the functions must be pure.
  • A promise's then looks like map, but it unwraps a promise returned by the function, so a promise is not a strict functor.
  • In category theory a functor maps types and the functions between them, preserving identity and composition.

Exercises

Exercise 1

A tree is a functor too. A tree node is an object { value, children }, where children is an array of nodes. Write mapTree(fn, tree): it applies fn to the value of every node and returns a new tree of the same shape, where every node has as many children as before, in the same order. Recursion from the "Recursion" lesson and the array's map will come in handy. The starter prints the tree after mapTree and checks both functor laws on it.

Starter code

// mapTree :: ((a -> b), Tree a) -> Tree b
// your code

const tree = {
  value: 1,
  children: [
    { value: 2, children: [] },
    { value: 3, children: [{ value: 4, children: [] }] },
  ],
}

const id = (x) => x
const inc = (x) => x + 1
const double = (x) => x * 2
// same :: (a, a) -> Boolean
const same = (a, b) => JSON.stringify(a) === JSON.stringify(b)

console.log(JSON.stringify(mapTree(double, tree)))
console.log(`identity: ${same(mapTree(id, tree), tree)}`)
console.log(`composition: ${same(mapTree((x) => double(inc(x)), tree), mapTree(double, mapTree(inc, tree)))}`)

Expected output

{"value":2,"children":[{"value":4,"children":[]},{"value":6,"children":[{"value":8,"children":[]}]}]}
identity: true
composition: true
Show solution
// mapTree :: ((a -> b), Tree a) -> Tree b
const mapTree = (fn, tree) => ({
  value: fn(tree.value),
  // the same children in the same order: the array's map keeps the structure
  children: tree.children.map((child) => mapTree(fn, child)),
})

const tree = {
  value: 1,
  children: [
    { value: 2, children: [] },
    { value: 3, children: [{ value: 4, children: [] }] },
  ],
}

const id = (x) => x
const inc = (x) => x + 1
const double = (x) => x * 2
// same :: (a, a) -> Boolean
const same = (a, b) => JSON.stringify(a) === JSON.stringify(b)

console.log(JSON.stringify(mapTree(double, tree)))
console.log(`identity: ${same(mapTree(id, tree), tree)}`)
console.log(`composition: ${same(mapTree((x) => double(inc(x)), tree), mapTree(double, mapTree(inc, tree)))}`)

Exercise 2

In the starter a list of products goes through three maps in a row: take the price, apply a 10% discount and format the string. The passes counter counts how many times the array was traversed. Relying on the composition law, get the same result after in a single pass: one call to map with the composition of the three functions via R.pipe or R.compose. After the refactoring the counter should show 1, and the result should match the previous one.

Starter code

const products = [
  { title: 'keyboard', price: 1000 },
  { title: 'mouse', price: 450 },
  { title: 'cable', price: 120 },
]

// how many times the array was traversed
let passes = 0
// map :: (a -> b) -> [a] -> [b]
const map = (fn) => (arr) => {
  passes += 1
  return arr.map(fn)
}

// getPrice :: Object -> Number
const getPrice = (product) => product.price
// discount :: Number -> Number, a 10% discount
const discount = (price) => price * 0.9
// format :: Number -> String
const format = (price) => price.toFixed(2)

// three passes
const before = map(format)(map(discount)(map(getPrice)(products)))
const passesBefore = passes

passes = 0
// your code: after, the same result in a single pass

console.log(JSON.stringify(before))
console.log(`passes before: ${passesBefore}`)
console.log(`passes after: ${passes}`)
console.log(`same result: ${JSON.stringify(after) === JSON.stringify(before)}`)

Expected output

["900.00","405.00","108.00"]
passes before: 3
passes after: 1
same result: true
Show solution
const products = [
  { title: 'keyboard', price: 1000 },
  { title: 'mouse', price: 450 },
  { title: 'cable', price: 120 },
]

// how many times the array was traversed
let passes = 0
// map :: (a -> b) -> [a] -> [b]
const map = (fn) => (arr) => {
  passes += 1
  return arr.map(fn)
}

// getPrice :: Object -> Number
const getPrice = (product) => product.price
// discount :: Number -> Number, a 10% discount
const discount = (price) => price * 0.9
// format :: Number -> String
const format = (price) => price.toFixed(2)

// three passes
const before = map(format)(map(discount)(map(getPrice)(products)))
const passesBefore = passes

passes = 0
// map(format) . map(discount) . map(getPrice) = map(format . discount . getPrice)
// R.pipe runs the functions left to right: getPrice first, then discount and format
const after = map(R.pipe(getPrice, discount, format))(products)

console.log(JSON.stringify(before))
console.log(`passes before: ${passesBefore}`)
console.log(`passes after: ${passes}`)
console.log(`same result: ${JSON.stringify(after) === JSON.stringify(before)}`)
